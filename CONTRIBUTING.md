# Вклад в разработку Красной Звезды

Спасибо за интерес к проекту.

Красная Звезда развивается непосредственно от официального репозитория Space Station 14. Поэтому при разработке мы стараемся использовать актуальную архитектуру и практики основной версии SS14, а не строить поверх неё отдельную несовместимую кодовую базу.

Перед началом работы рекомендуем ознакомиться с:

- [организацией кодовой базы SS14](https://docs.spacestation14.com/en/general-development/codebase-info/codebase-organization.html);
- [рекомендациями Space Station 14 по Pull Request](https://docs.spacestation14.com/en/general-development/codebase-info/pull-request-guidelines.html);
- [правилами лицензирования Красной Звезды](LICENSE.md);
- [Contributor License Agreement](CONTRIBUTOR_LICENSE_AGREEMENT.md).

## Основной upstream

Основным upstream Красной Звезды является:

`space-wizards/space-station-14`

Другие форки Space Station 14 могут использоваться как источник отдельных идей, механик или ассетов, но не определяют архитектуру проекта.

Если изменение достаточно универсально и может быть полезно Space Station 14 в целом, желательно реализовать его без зависимости от специфичного контента Красной Звезды.

Такой код проще поддерживать и при необходимости отправить обратно в Space Wizards.

## Контент Красной Звезды

Ресурсы, существующие только в нашем проекте, по возможности следует отделять от ресурсов Space Station 14.

Для этого используются каталоги `_RedStar`, например:

```text
Resources/Prototypes/_RedStar/
Resources/Textures/_RedStar/
Resources/Audio/_RedStar/
Resources/Locale/ru-RU/_RedStar/
Resources/Maps/_RedStar/
```

Для C# отдельная структура нужна только тогда, когда код действительно специфичен для Красной Звезды.

Общие системы, компоненты и API, которые могут быть полезны основной версии SS14, не следует искусственно помещать в RedStar-specific namespace или каталог.

## Изменение кода Space Station 14

Не добавляйте комментарии вроде:

```text
// RedStar
// RS14-start
// RS14-end
```

вокруг каждого изменения.

Git уже хранит историю проекта и позволяет увидеть различия относительно Space Station 14.

Вместо этого старайтесь:

- делать небольшие и понятные изменения;
- не форматировать код вне задачи;
- не смешивать несколько несвязанных изменений в одном Pull Request;
- использовать существующие решения Space Station 14 там, где они подходят;
- не создавать собственные аналоги уже существующих API без необходимости.

## Порты из других проектов

Интересная механика из другого форка вполне может попасть в Красную Звезду.

Но перенос должен быть осознанным.

Перед портом:

1. Проверьте лицензию исходного материала.
2. Укажите исходный репозиторий и, по возможности, конкретный commit или Pull Request.
3. Сохраните необходимую атрибуцию.
4. Убедитесь, что лицензия допускает использование материала в Красной Звезде.
5. Адаптируйте реализацию под актуальную архитектуру проекта вместо слепого копирования старого кода.

Код, происходящий из стороннего AGPL-проекта, нельзя отправлять в Space Wizards под MIT без соответствующих прав от его авторов.

## Ассеты

Для спрайтов, звуков и других ассетов особенно важно сохранять происхождение материала.

При добавлении ассета должны быть известны:

- автор;
- источник;
- лицензия;
- необходимая атрибуция.

Для RSI используйте существующий формат `meta.json`.

Если ассет является переработкой чужой работы, это также должно быть указано.

## RobustToolbox

`RobustToolbox` является git submodule.

Не изменяйте движок в рамках обычного контентного PR без необходимости.

Если изменение требуется именно в RobustToolbox, его лучше рассматривать отдельно.

Перед отправкой PR также проверяйте, что в изменения случайно не попал новый указатель submodule.

## Pull Request

Один Pull Request должен решать одну логически связанную задачу.

Перед отправкой:

- просмотрите `git diff`;
- проверьте список изменённых файлов;
- удалите случайные изменения;
- убедитесь, что нет лишнего форматирования;
- протестируйте изменение;
- соберите проект, если изменение затрагивает код.

Базовая проверка:

```shell
dotnet build
```

Если для затронутой системы существуют подходящие тесты, запустите их отдельно.

## Изменения для Space Wizards

Мы приветствуем изменения, которые могут быть полезны не только Красной Звезде.

Если ваш код достаточно общий, его можно подготовить для отправки в Space Wizards.

При этом Pull Request в Space Wizards должен соответствовать их собственным актуальным правилам разработки, лицензирования и оформления.

## Лицензирование вклада

Отправляя исходный код в Красную Звезду, вы соглашаетесь с
[Contributor License Agreement](CONTRIBUTOR_LICENSE_AGREEMENT.md).

Авторские права на ваш собственный код остаются у вас.

Ваш вклад используется в Красной Звезде под AGPL-3.0-or-later.

Одновременно вы предоставляете ограниченное разрешение отправить принадлежащую вам часть этого кода в проекты Space Wizards Federation под MIT.

Это разрешение не относится к стороннему коду, правами на который вы не обладаете.
